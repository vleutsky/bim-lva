37. [x] **Метка XYZ** — кнопка 📍: клик по модели ставит точку и подпись с
    абсолютными X, Y, Z (метры). Точка перетаскивается по геометрии, подпись
    висит на полке (выноска + горизонтальная черта) и таскается отдельно.
    Кнопка 📋 открывает список меток: перелёт к метке, копирование тройки,
    удаление, выгрузка всех в буфер. Слой свой — «Очистить замеры» метки не
    трогает. Числа считаются тем же путём, что и строка состояния; smoke
    сверяет подпись с пересчётом и проверяет перетаскивание
38. [x] **Линейка 2D/3D/уклон** — режим замера «2D/3D/i»: по двум точкам сразу

39. [x] **Обновить модель** — в контекстном меню дерева «⟳ Обновить модель» и

42. [x] **Ноль сцены помнит свои оси** — первая крупная модель задаёт общий ноль,

    хранится вместе с нулём, пересчёт один на всех.
    Проверка — `npm run test-mixed-origin`

43. [x] **Ортогональная проекция** — кнопка «Персп / Орто» на видовом кубе.
    Камера подменяется целиком (OrbitControls, лучи, проекция подписей берут
    её из одной переменной), охват кадра при переключении сохраняется.
    Для планов и 2D-чертежей — обязательна. В `npm run smoke` проверяется не
    флаг, а что в орто по сцене по-прежнему можно попасть кликом

44. [x] **Объектная привязка** — кнопка ⊹ (включена по умолчанию): вершины,
    середины и точки на рёбрах. Работает и для черчения полилиний, и для
    замеров. Кандидат выбирается по расстоянию в **экранных пикселях**, поэтому
    порог не надо менять при зуме. Линии из DWG/DXF обрабатываются отдельно: у
    них нет грани, зато есть отрезок — привязка к концам осей нужна чаще всего.
    Под курсором показывается маркер: квадрат — вершина, треугольник —
    середина, круг — ребро. Проверка в `npm run smoke`

45. [x] **Сущности DWG/DXF поштучно** — линии, дуги, полилинии, грани и точки
    чертежа стали отдельными объектами: видны в дереве под своим слоем,
    выбираются кликом в сцене, подсвечиваются и показывают слой, тип, число
    вершин, длину и мировой центр. Геометрия при этом **осталась склеенной по
    слоям** — иначе на плане с десятками тысяч линий было бы столько же вызовов
    отрисовки; сущность опознаётся по диапазону вершин в общем буфере.
    В дереве показываются первые 500 на слой (больше DOM не выдержит),
    в сцене выбираются все. Проверки в `npm run smoke`: дерево, выбор поштучно,
    свойства и границы бинарного поиска по вершинам

46. [x] **Тело по оси** — кнопка ⬒: осью служит выбранная линия чертежа DWG/DXF
    или последняя начерченная полилиния, сечение задаётся размерами
    (прямоугольник, трапеция для канав и насыпей, круг, труба со стенкой) плюс
    смещение по высоте. Сечение ведётся параллельным переносом системы
    координат — на поворотах тело не перекручивается. В отчёте длина оси,
    площадь сечения и объём. Тела выгружаются в DXF гранями 3DFACE на слой
    LVA_SOLID. Математика проверяется числами в `npm run smoke`: объём равен
    площади × длину, габарит совпадает с сечением, у трубы — площадь кольца

47. [x] **Как файл сел и переключатель на место** — в «Анализ → CRS» у каждого
    файла подписано, что с его координатами сделали: «вычтен общий ноль сцены»
    или красным «ПОСАЖЕН В СВОЙ ЦЕНТР — мировые координаты потеряны» (раньше
    это происходило молча, и модель просто оказывалась не там; теперь ещё и
    уведомление при загрузке). Рядом кнопка «⇲ Поставить по мировым
    координатам»: считает разницу между текущим положением и габаритом,
    снятым при загрузке, и возвращает файл на место. Проверка в
    `npm run test-geo-seq`: модель нарочно сдвигают и возвращают — остаток 0.000 м

48. [x] **Цепочка размещения IFC** — в «Диагностике IFC» кнопка «🔗 Цепочка
    размещения»: второй проход по файлу строит индекс всех IfcLocalPlacement /
    IfcAxis2Placement3D / IfcCartesianPoint / IfcDirection, находит IfcSite и
    один типовой элемент, и печатает координаты на КАЖДОМ шаге цепочки
    PlacementRelTo — от элемента до корня, плюс отдельно резолвит
    `IfcGeometricRepresentationContext.WorldCoordinateSystem` (мировой сдвиг
    может лежать и там, вне цепочки размещения — так подтвердилось на реальном
    файле АР). Каждый пропуск отмечен явно («не нашлось» — RelativePlacement=$
    или дырка в индексе), а не тихо заменён нулём — иначе не отличить «файл так
    написан» от «мой парсер не справился». Проверено фикстурами: оторванный
    элемент (`PlacementRelTo=$`) и площадка на identity-размещении с реальным
    сдвигом только в WCS

49. [x] **Автокоррекция WorldCoordinateSystem** — если IFC привезён с ODA
    (Renga, nanoCAD) и мировой сдвиг лежит не в цепочке `IfcLocalPlacement`, а
    в `IfcGeometricRepresentationContext.WorldCoordinateSystem`, вьювер находит
    его и применяет сам: разбирает начало файла, строит матрицу коррекции в
    осях фрагментов через ту же матрицу, что разворачивает сцену, и сдвигает
    геометрию перед вычитанием общего нуля. Срабатывает только когда похоже на
    именно этот случай — `IfcMapConversion` нет и геометрия ещё в локальном
    нуле, — иначе нормально геопривязанный файл получил бы двойной сдвиг.
    Найдено и подтверждено на реальном файле кнопкой «🔗 Цепочка размещения» в
    «Диагностике IFC» (см. п. 48). Проверено в `npm run test-rotated`.
    Поворот у ODA-экспорта иногда лежит не в `RefDirection` самого
    `WorldCoordinateSystem`, а в `TrueNorth` контекста (направление истинного
    севера относительно оси Y модели) — вьювер читает и его как запасной
    источник угла, формула другая (`atan2(Tx, Ty)`, а не `atan2(Ty, Tx)`).
    Подтверждено владельцем на реальном файле АР («Село как родное»).
50. [x] **Выбрать подобные** — в контекстном меню сцены (ПКМ по элементу)
    пункт «🧲 Выбрать подобные»: для IFC — тот же класс во всех загруженных
    моделях федерации, для DXF/DWG — та же сущность (линия/полилиния/дуга/…)
    на том же слое в пределах файла. Проверено в `npm run smoke` (оба пути).
51. [x] **Список полилиний + радиусы сопряжения** — кнопка «📐 Полилинии» в
    «Создать 2Д/3Д»: таблица начерченных полилиний (переименование, длина,
    приближение камерой, удаление), «✎» раскрывает точки — координаты
    (абсолютные, только просмотр), удаление отдельной вершины и радиус
    сопряжения в любой внутренней вершине (не в первой/последней) — та же
    операция, что «вписать радиус» в вершину трассы в Civil 3D. Радиус
    заменяет угол дугой (касательная `R/tan(α/2)`, центр на биссектрисе);
    если отрезки короче, чем нужно для радиуса, он усекается автоматически
    с уведомлением. Экспорт в DXF — тем же путём, что и прямые полилинии:
    дуга уходит частой ломаной (`buildDxf` не знает о дугах отдельно, ему
    все точки одинаковы). Проверено в `npm run smoke`: подсчёт точек и длины
    после сопряжения, переименование и общее удаление через список.

52. [x] **Полилинии: стиль, правка числами, выбор в сцене** — развитие п. 51.
    Цвет и толщина в строке списка; толщина работает потому, что линии
    переведены на `Line2` — у обычной `THREE.Line` в WebGL `linewidth` всегда
    1 px, это ограничение самого WebGL. При черчении тянется «резиновая нить»
    от последней точки к курсору (с учётом привязки) — раньше первый отрезок
    был невиден до второго клика. В таблице вершин правятся **H** (абсолютная
    отметка), **L** (длина отрезка до следующей вершины — двигает её вдоль
    текущего направления), **i‰** (уклон отрезка — меняет только отметку
    конца) и **R** (радиус сопряжения). Двигается всегда одна вершина, хвост
    за собой не тянется. По линии в сцене можно кликнуть — она раскроется в
    панели; ПКМ по ней даёт «Свойства», «Вписать кривую в этот угол…» (радиус
    ложится в вершину, ближайшую к точке правого клика — не во все сразу),
    «Тело по этой оси», «Удалить». Панель плавающая (`floating-panel`,
    общий помощник `createFloatingPanel` — на нём же теперь окно коллизий),
    сцену не блокирует и таскается за заголовок. Проверено в `npm run smoke`:
    цвет и толщина доходят до материала, отметка/длина/уклон дают ожидаемые
    числа, нить появляется после первой точки.

53. [x] **Полилинии: правка, замыкание, профиль, картограмма** — большой блок
    поверх пп. 51–52.
    - **Ручки вершин** в сцене: у раскрытой полилинии показываются маркеры,
      их тянут мышью (луч + привязка, как при черчении). Раньше подсказка
      обещала это, а кода не было — X/Y не правились никак.
    - **Замкнутый контур** (кнопка ⭘): углами становятся все вершины, включая
      крайние; считается площадь в плане; в DXF уходит флагом, а не повторной
      вершиной.
    - **Вставка вершины** (⊕ в строке) и **продолжение** полилинии с любого
      конца через контекстное меню — имя, цвет, толщина и радиусы сохраняются.
    - **Ввод числами** при черчении: длина, азимут (по часовой от севера) и
      превышение; пустой азимут продолжает прежним направлением, Enter ставит
      точку.
    - **Фильтр привязки**: галочки вершина/середина/ребро, выбор запоминается.
    - **Дуги в DXF**: сопряжение 2D-полилинии уходит настоящей дугой через
      bulge (код 42). У 3D bulge в R12 нет — там осталась ломаная, и это
      честно возвращается в `arcs: false`.
    - **Продольный профиль по оси** (〰): отметки земли лучом вниз, пикетаж,
      рабочие отметки, CSV, «посадить ось на землю». Промах луча даёт разрыв и
      прочерк, а не подставленный ноль.
    - **Картограмма** (⛰) по замкнутому контуру: метод квадратов, выемка,
      насыпь, баланс, диапазон рабочих отметок. Площадь считается по ячейкам с
      найденной землёй — только она соответствует посчитанному объёму.
    Проверено в `npm run smoke` числами: перетаскивание сдвигает вершину,
    площадь контура сходится с формулой шнурков, bulge — с `tan(Δ/4)` вместе
    со знаком, рабочая отметка равна «ось минус земля», а подъём проектной
    отметки на Δ меняет баланс картограммы ровно на «площадь × Δ».

54. [x] **Откосы до рельефа** (кнопка «△ Откосы» в списке полилиний) — от
    каждой точки линии откос идёт по нормали в плане (влево / вправо / в обе
    стороны) до пересечения с рельефом: выше земли на бровке — насыпь (1:m,
    умолчание 1.5), ниже — выемка (1:m, умолчание 1). На выходе: поверхность
    откоса в сцене (раскраска по насыпи/выемке), линия выхода на землю —
    отдельной редактируемой полилинией (уходит в DXF, как и любая другая), и
    объёмы насыпи/выемки по методу средних площадей. Где рельеф не найден или
    откос не дотянулся за максимальный вылет — сечение выпадает из площади,
    линии и объёма (не подставляем нули), а не роняет весь расчёт; на вогнутых
    углах соседние сечения могут налезть друг на друга — честно не вычищается.
    Проверено в `npm run smoke` числами (`createPolylineFromPoints` +
    `buildSlopeOnPolyline`): на ровной площадке экзит-дистанция и площадь
    сечения сходятся с аналитической формулой `d = m·(z_бровки − z_земли)`,
    а объём — с «площадь × длина» для случая насыпи и выемки по отдельности;
    отдельно проверено, что маленький максимальный вылет честно даёт
    пропущенные сечения и нулевой объём, а не подставленное число.
    У замкнутого контура середина заполняется как площадка (ear clipping в
    плане — иначе в TIN дыра до исходного рельефа), у разомкнутой линии
    торцы закрываются откосом вдоль оси. Готовый TIN выгружается в Civil 3D:
    DXF R12 слоем `LVA_SLOPE` (3DFACE, абсолютные метры) и LandXML 1.2
    Surface (`Pnts`/`Faces`, northing easting elev — тот же формат, который
    вьювер сам читает). Проверено в `npm run smoke`: квадрат 4×4 даёт ровно
    2 треугольника середины, LandXML точка 1 совпадает с TIN, число `<F>`
    равно числу граней, в DXF есть слой `LVA_SLOPE`.

## Вендоры и проверки

- Зависимости лежат локально в `assets/vendor/` — three, three-mesh-bvh,
  web-ifc (+ wasm), geotiff, jszip, qrcode, dwgdxf (+ wasm), supabase, шрифты. Сайт остаётся
  статикой: `assets/vendor/` коммитится, шага сборки при деплое нет.
- Пересобрать после смены версии в `package.json`: `npm ci && npm run vendor`.
  Версии видны в `assets/vendor/VERSIONS.json`.
- На CDN осознанно оставлены pyodide (DXF через ezdxf) и gdal3.js (ECW) —
  десятки мегабайт ради редкой операции.
- `npm run serve` — локальный просмотр на http://127.0.0.1:8080. Двойным щелчком
  по файлу вьювер не открыть: ES-модули, importmap и wasm требуют HTTP.
- `npm run portfolio` — пересобрать `portfolio.html` из `index.html`. Это версия
  сайта для отклика на вакансии: без блока «Разработка под заказ», без кнопки
  доната, раздел услуг переписан в «Навыки». Ссылку в hh давать на неё, без
  якоря: `https://vleutsky.github.io/bim-lva/portfolio.html`
- `npm run test-license` — проверка формата лицензии на совместимость с
  `LicenseGate` из репозитория LvaBim: каноническая строка, формат дат .NET
  (семь знаков дробной части — иначе подпись не сойдётся после разбора JSON),
  RSA-SHA256/PKCS#1, подделки, просрочка, привязка к машине.
- `npm run edge-bundle` — пересобрать `bundled.ts` для развёртывания функции
  через дашборд без CLI. Правки вносить в исходники, не в сборку.
- Лицензии: инструкция по развёртыванию и проверка ключа в плагине (C#) —
  `supabase/functions/license-issue/README.md`. Ключи выпускает только сервер;
  на статическом сайте защищённого места нет и быть не может.
- `npm run check-site` — проверка страниц: заглушки вроде `YOUR_LINK_HERE`,
  битые внутренние ссылки, пустые якоря, локальные 404. Гонять перед рассылкой
  резюме.
- `npm run smoke` — дымовой тест в Chromium: страница, загрузка IFC, пикинг,
  уведомления, прогон коллизий. Гоняйте перед merge в `main`.
- Pages отдаёт `main`; preview-URL для веток у Pages нет. Правки вьювера сначала
  живут в `bim-lva-composer-ifc-preview.html` (`npm run preview`), и только
  после проверки — в рабочем файле.
- `node tools/bench-pick.mjs [N]` — замер отклика на клик.
- `bim-lva-composer-ai.html` пока остался на CDN: вендоры и BVH в него не
  переносились.
